Control de versiones

Definición

Un sistema de control de versiones (VCS) registra los cambios hechos a los archivos de un proyecto a lo largo del tiempo. Permite volver a versiones anteriores, saber quién cambió qué y trabajar en equipo sin pisarse el trabajo.

Tipos de sistemas

TipoCómo funcionaVentajasDesventajas
Local (RCS)Guarda versiones en una base de datos en el mismo equipo.Simple, sin red.Sin colaboración; un fallo de disco pierde todo.
Centralizado (SVN, CVS)Un servidor central guarda el historial; cada usuario descarga una copia de trabajo.Control de permisos fácil, flujo sencillo.Punto único de falla; requiere conexión para casi todo.
Distribuido (Git, Mercurial)Cada usuario clona el repositorio completo con todo su historial.Trabajo sin conexión, ramas rápidas, respaldo natural.Curva de aprendizaje; historiales grandes pesan más.

Funcionamiento

Se trabaja en una copia local, se agrupan cambios en commits (instantáneas con autor, fecha y mensaje), se crean ramas para desarrollar en paralelo y se fusionan (merge). En Git, push y pull sincronizan con el repositorio remoto (GitHub, GitLab).

Rastreo y gestión de cambios

  • git status / git diff: ver qué cambió.
  • git log: historial de commits.
  • git blame: quién modificó cada línea.
  • git revert / git checkout: deshacer o volver a una versión.
  • git tag: marcar versiones publicadas.

Ejemplo

git init
git add .
git commit -m "Pantalla de login"
git checkout -b feature/sensores
git push origin feature/sensores

Persistencia y acceso a datos

Definición y características

Persistencia es la capacidad de conservar los datos de una app aunque se cierre o el dispositivo se reinicie. Características: durabilidad, consistencia, acceso eficiente, seguridad y capacidad de sincronización.

Formas de persistencia

FormaDescripciónDatos que almacena
ArchivosPreferencias (SharedPreferences, UserDefaults), almacenamiento interno/externo.Configuraciones, texto, JSON, imágenes, audio, caché.
BD localSQLite, Room, Realm; funciona sin conexión.Datos estructurados: usuarios, tareas, historiales.
BD remotaServidor accedido mediante servicios web (REST/JSON), p. ej. Firebase.Datos compartidos entre usuarios y dispositivos.

Control de acceso a medios persistentes

  • Biblioteca de clases: APIs del SDK (File, SharedPreferences, Context) que abstraen el acceso.
  • Clases de SQLite: SQLiteOpenHelper, SQLiteDatabase, Cursor, ContentValues para crear y consultar tablas.
  • Mapeo relacional de objetos (ORM): convierte objetos en filas (Room, Core Data, GreenDAO) y evita escribir SQL manual.

Autenticación y consumo de servicios web

  1. El usuario envía credenciales por HTTPS.
  2. El servidor valida y devuelve un token (JWT/OAuth).
  3. La app guarda el token de forma segura (Keystore/Keychain).
  4. Cada petición incluye el token en el encabezado Authorization.
  5. La app procesa la respuesta JSON y la muestra o guarda localmente.

Ejemplo

@Entity data class Tarea(@PrimaryKey val id: Int, val titulo: String)
@Dao interface TareaDao { @Query("SELECT * FROM Tarea") fun todas(): List<Tarea> }

@GET("tareas") suspend fun obtener(@Header("Authorization") t: String): List<Tarea>

Gestión de sensores

Definición

Los sensores son componentes de hardware que miden magnitudes físicas del entorno o del dispositivo y las entregan como datos a las apps.

Tipos

  • Movimiento: acelerómetro, giroscopio.
  • Posición: GPS, magnetómetro, orientación.
  • Ambientales: luz, proximidad, temperatura, presión, humedad.
  • Biométricos y otros: huella, cámara, micrófono, ritmo cardiaco.

Proceso de gestión

  1. Habilitación: declarar permisos y verificar que el sensor exista.
  2. Obtención: registrar un listener y elegir la frecuencia de muestreo.
  3. Procesamiento: filtrar, interpretar y usar los valores; liberar el sensor al salir.
val sm = getSystemService(SENSOR_SERVICE) as SensorManager
val acel = sm.getDefaultSensor(Sensor.TYPE_ACCELEROMETER)
sm.registerListener(this, acel, SensorManager.SENSOR_DELAY_NORMAL)
override fun onSensorChanged(e: SensorEvent) { val x = e.values[0] }

Uso de recursos multimedia

Definición

Son los elementos de imagen, sonido, video y animación que enriquecen la interfaz y la experiencia de una app móvil.

Tipos

  • Imágenes: PNG, JPG, WebP, vectores (SVG/VectorDrawable).
  • Audio: MP3, OGG, efectos y música.
  • Video: MP4, streaming.
  • Animaciones: Lottie, AnimatedVectorDrawable, transiciones.
  • Elementos visuales dinámicos: gráficos, canvas, vistas personalizadas.

Estructura del proyecto (Android)

  • res/drawable: imágenes y vectores.
  • res/mipmap: íconos de la app.
  • res/raw: audio y video sin procesar.
  • assets: archivos accedidos como flujo.
  • res/anim: animaciones XML.

Componentes de software

ImageView y Glide/Coil (imágenes), MediaPlayer y ExoPlayer (audio/video), VideoView, SoundPool (efectos cortos), Animator y Lottie (animación).

Servicios y notificaciones

Definición

Los servicios son componentes que realizan operaciones sin interfaz visible; las notificaciones informan al usuario de eventos fuera de la app.

Tareas en segundo plano

Trabajo que continúa sin que la app esté en pantalla: sincronizar datos, descargar archivos, reproducir música. En Android se usan WorkManager, servicios en primer plano y corrutinas; en iOS, Background Tasks.

Notificaciones

Se crean con un canal (NotificationChannel), un constructor (NotificationCompat.Builder) y el NotificationManager. Pueden ser locales o push (FCM/APNs) y requieren permiso en versiones recientes.

Proceso de implementación

  1. Proveedor de contenido: extender ContentProvider, definir URI y declararlo en el manifiesto para compartir datos.
  2. Tarea en segundo plano: crear un Worker, definir restricciones y encolarlo.
  3. Notificación: crear canal, construir y llamar a notify().

Cómputo en la nube

Firebase (autenticación, base de datos, FCM), AWS Amplify, Google Cloud, Azure Mobile Apps: ofrecen almacenamiento, funciones sin servidor, analítica y mensajería.

Librerías y toolkits para desarrollo móvil

¿Qué son?

Una librería es un conjunto de funciones o clases reutilizables que tu código llama para resolver una tarea concreta. Un toolkit es un conjunto más amplio de herramientas, componentes y bibliotecas para construir aplicaciones completas.

Librerías especializadas

  • Red: Retrofit, OkHttp, Alamofire.
  • Imágenes: Glide, Coil, Picasso.
  • Datos: Room, Realm, Gson/Moshi.
  • Inyección y asincronía: Hilt, Coroutines, RxJava.

Depuración y seguridad

¿Qué es?

La depuración es encontrar y corregir errores del código. La seguridad es proteger los datos, la comunicación y el acceso de la app frente a amenazas.

Herramientas de depuración

  • Logcat: registros del sistema y de la app.
  • Debugger del IDE: puntos de interrupción, ejecución paso a paso, inspección de variables.
  • Android Studio Profiler: CPU, memoria, red y energía.
  • Layout Inspector y emuladores: revisar interfaz y probar dispositivos virtuales.
  • Xcode Instruments (iOS).

Buenas prácticas de seguridad

  • Usar HTTPS y validar certificados.
  • Guardar secretos en Keystore/Keychain.
  • Pedir solo los permisos necesarios.
  • Ofuscar el código (R8/ProGuard) y validar entradas.
